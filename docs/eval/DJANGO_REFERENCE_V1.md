## middleware — Middleware execution

For a normal synchronous request, in what order does middleware run, and why can a middleware return a response early without continuing to the view?

- **build-chain**: Middleware is instantiated in reverse configuration order, wrapping the downstream handler at each level so requests enter at the first configured item. [django/core/handlers/base.py:39-40](https://github.com/django/django/blob/f59aef2ee9b5c988fd4179d8f2835030bd76297c/django/core/handlers/base.py#L39-L40), [django/core/handlers/base.py:61-61](https://github.com/django/django/blob/f59aef2ee9b5c988fd4179d8f2835030bd76297c/django/core/handlers/base.py#L61-L61), [django/core/handlers/base.py:95-95](https://github.com/django/django/blob/f59aef2ee9b5c988fd4179d8f2835030bd76297c/django/core/handlers/base.py#L95-L95)
- **call-chain**: The completed handler is saved as the middleware chain, which ordinary requests call directly. [django/core/handlers/base.py:102-102](https://github.com/django/django/blob/f59aef2ee9b5c988fd4179d8f2835030bd76297c/django/core/handlers/base.py#L102-L102), [django/core/handlers/base.py:140-140](https://github.com/django/django/blob/f59aef2ee9b5c988fd4179d8f2835030bd76297c/django/core/handlers/base.py#L140-L140)
- **request-short-circuit**: Compatibility middleware runs the request hook first, calls downstream only if no response was returned, then runs the response hook. [django/core/handlers/base.py:184-192](https://github.com/django/django/blob/f59aef2ee9b5c988fd4179d8f2835030bd76297c/django/core/handlers/base.py#L184-L192), [django/core/handlers/base.py:197-197](https://github.com/django/django/blob/f59aef2ee9b5c988fd4179d8f2835030bd76297c/django/core/handlers/base.py#L197-L197)

- **restore-autocommit**: The outermost exit restores autocommit, or clears the connection if the transactional connection was closed. [django/db/transaction.py:303-307](https://github.com/django/django/blob/f59aef2ee9b5c988fd4179d8f2835030bd76297c/django/db/transaction.py#L303-L307)
